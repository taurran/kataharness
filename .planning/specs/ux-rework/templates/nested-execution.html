Nested execution — three tiers of legibility

The answer to “how do I follow subagents running subagents”: the statusline shows depth at a glance, the run board shows the whole tree, and every transcript line names its lineage.

tier 1 · THE STATUSLINE — always visible, ~1s refresh, one line: 改│KataHarness ▓▓▓▓▓▓░░░░ 61% │ fable │ exec 3/6 │ crew W1▸2 W2 W3▸1 W1▸2 = worker W1 has 2 nested children cooking — depth at a glance tier 2 · THE RUN ┌─ run board — backlog-burn-01 · exec · wave 2 of 3 ───────────┐ │● W1 config validator building · 12m · 41k tok │ │ ├ ● W1.1 test author red→green · 4/9 cases │ │ └ ● W1.2 docs sync waiting on W1.1 │ │● W2 /kata-loop command at the gate · judge running │ │ └ ● W2.1 judge (fresh ctx) verifying claims · 2m │ │○ W3 code-map measurement queued · starts in wave 3 │ │ │ │ agents 5 · 3 direct + 2 nested · deepest branch 2 · all owned│ └──────────────────────────────────────────────────────────────┘ — /kata-status, the full tree on demand: ┌─ run board — backlog-burn-01 · exec · wave 2 of 3 ───────────┐ │● W1 config validator building · 12m · 41k tok │ │ ├ ● W1.1 test author red→green · 4/9 cases │ │ └ ● W1.2 docs sync waiting on W1.1 │ │● W2 /kata-loop command at the gate · judge running │ │ └ ● W2.1 judge (fresh ctx) verifying claims · 2m │ │○ W3 code-map measurement queued · starts in wave 3 │ │ │ │ agents 5 · 3 direct + 2 nested · deepest branch 2 · all owned│ └──────────────────────────────────────────────────────────────┘ tier 3 · IN THE TRANSCRIPT — every worker line carries its lineage: ▏[W1.1] 9 cases written · 4 green · rerunning the red five ▏[W2→judge] claim 2 of 3 reproduced independently

Worker IDs are hierarchical (W1 → W1.1) so lineage is in the name itself; the board is depth-capped with rollup counts if a tree ever gets deeper than readable; “all owned” = every branch traces to a dispatch record — no orphan agents.
